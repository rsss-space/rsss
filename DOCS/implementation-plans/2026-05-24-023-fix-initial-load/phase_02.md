# Phase 2: Add `preconnect` hint for `js.stripe.com`

**Goal:** Warm DNS/TLS for Stripe's origin in parallel with page render
so that when the user eventually opens settings and triggers
`loadStripe()`, the SDK fetch starts with the connection pre-warmed
(~100-300ms saved).

**Architecture:** One added `<link>` tag in the source HTML. No JS
changes, no new modules. The `crossorigin` attribute is required so the
preconnected socket is reused by the (CORS-enabled) Stripe.js fetch.

**Tech Stack:** Static HTML.

**Scope:** Phase 2 of 8. Independent of Phase 1 (can land in either
order).

**Codebase verified:** 2026-05-24

**Key facts from investigation:**
- The design says edit `public/index.html`. There is no
  `public/index.html` in the repo. The actual source HTML is at the
  repo root: `/Users/nick/code/rsss/index.html` (used by Vite during
  `npm run dev` and as the template for the production build).
- `public/client/index.html` exists but is the *built* output
  (regenerated by Vite on every build, with hashed asset filenames in
  lines 22-23). Editing it directly is futile.
- No existing preconnect or dns-prefetch hints in either file.

### Task 1: Add the preconnect link tag

**Verifies:** 023-fix-initial-load.AC8.2

**Files:**
- Modify: `index.html` (repo root, the Vite source template)

**Implementation:**

In `/Users/nick/code/rsss/index.html`, add a single `<link>` tag in the
`<head>` block. Place it immediately after line 5 (the viewport meta
tag) and before line 6 (the `<title>`), so the preconnect fires as
early as possible in head parsing. Keep the `crossorigin` attribute
present (its presence — with or without a value — is what makes the
preconnected socket reusable by the CORS Stripe.js fetch).

Insert this line (with the indentation matching surrounding meta tags):

```html
    <link rel="preconnect" crossorigin href="https://js.stripe.com">
```

The resulting `<head>` prefix should look like:

```html
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <link rel="preconnect" crossorigin href="https://js.stripe.com">
    <title>RSSS - RSS Reader</title>
```

Do not edit `public/client/index.html` — Vite regenerates it on every
build from the root `index.html`.

**Verification:**

Run: `npm run build`
Expected: Build succeeds.

Check the built file:

```bash
grep "preconnect" /Users/nick/code/rsss/public/client/index.html
```

Expected output:

```
    <link rel="preconnect" crossorigin href="https://js.stripe.com">
```

Manual check (per the `run` skill):
1. Start the dev server and load the home route in a fresh tab with
   "Disable cache" on.
2. In DevTools' Network panel, filter for `stripe`.
3. You should see an early DNS lookup / TLS handshake row for
   `js.stripe.com` with *no corresponding resource fetch* (the
   preconnect warms the connection without fetching).
4. The Network panel will not list the preconnect itself as a real
   request — checking for it via the "Network log" requires either
   filter "all" + sorting by start time, or the "Connection" column
   in Performance recording. A simpler check: confirm the `<link>` tag
   is present in the served HTML via View Source (or `curl localhost:<port>`).

**Commit:**

```bash
git add index.html
git commit -m "perf: preconnect to js.stripe.com to warm DNS/TLS

Adds a <link rel=\"preconnect\" crossorigin href=\"https://js.stripe.com\">

parallel with page render. This shaves ~100-300ms off the eventual
Stripe.js fetch when the user opens the payment-method modal, without
adding a script-tag injection on the home critical path.

Part of 023-fix-initial-load."
```
